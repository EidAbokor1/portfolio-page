02 / Data & cost engineering#

S3 attribution & storage optimisation

WHAT I DIDI built a tool to assign S3 objects to projects, analysed old object versions, and tested tagging reliability.

~99% allocatedOne ~803 TiB dataset

Assigned roughly 99% of one 803 TiB dataset to projects. Separate analysis identified about $60k/year in potential storage savings.

S3 InventoryAthenaLambdaS3 Batch Operations
Details+

Project attribution

Storage ownership was unclear. I used S3 Inventory, Athena, Batch Operations, and Lambda to tag objects with their project. Objects without enough evidence stayed unallocated.

The process used version-aware manifests, dry runs, backups, and reconciliation. Existing unrelated tags were preserved.

Old object versions

Inventory analysis found about 1.56 million noncurrent versions using roughly 210 TiB. This identified an estimated $60k in annual storage savings, subject to archive or deletion decisions. It is an estimate, not confirmed savings.

Tagging reliability

Higher Lambda concurrency caused more processing failures in testing. Lowering it improved reliability. I also explored ECS workers for more control over request rates and retries; moving runtimes alone would not remove pressure on S3.
